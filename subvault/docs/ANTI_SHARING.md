# 为什么用户仍能分享单节点

订阅链接是一种配置分发机制。客户端成功导入后，本地必须保存节点地址、端口、UUID、密码或密钥，否则无法建立代理连接。因此下面这些做法只能增加操作难度，不能真正防止分享：

- 隐藏复制按钮；
- 只显示二维码；
- 对订阅正文再做一次 Base64；
- 限制订阅 URL 的下载 IP；
- 修改节点显示名称。

## 可执行的防分享架构

每份订阅应获得独立节点凭证。节点侧采集器维护 `订阅 → 节点用户` 映射，周期性读取 Xray stats、sing-box API 或节点日志：

- 超过允许的活跃 IP 数时，临时停用该用户；
- 流量耗尽或订阅到期时，删除或禁用用户；
- 管理员解除绑定、续期或重置配额时，重新启用用户；
- 凭证泄露时，只轮换该订阅，不影响其他朋友。

即使使用独立凭证，也无法在不控制客户端的情况下准确识别物理设备；能可靠执行的是凭证、源 IP、并发连接和流量策略。

## 下一阶段接入需要的信息

节点代理程序不能盲目修改服务器配置。实现前需要确定：

- 节点使用 Xray、sing-box、3x-ui、x-ui、Hiddify 还是其他面板；
- 节点是否与 SubVault 在同一台 VPS；
- 入站协议及配置文件/API 位置；
- 是否允许为每位订阅用户创建独立凭证；
- 希望按瞬时并发 IP、24 小时活跃 IP，还是两者共同限制。
